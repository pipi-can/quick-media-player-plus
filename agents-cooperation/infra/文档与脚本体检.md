  目标：脚本语法错、Markdown 结构错，**在提交前**就被拒掉，而不是靠人记得手工查一遍。
  背景：块 1 收尾时手工体检，查出两处真错（pitfalls.md 行内裸三连反引号、
  coop-find.sh --help 退 1），但那次检查是一次性的——谁下次改了文档都不会再跑。
  这正是我们自己写进 pitfalls.md 的那条教训："没有机器检查能证明"。

  设计：
  - 新脚本 coop-docs-check.sh，只读，退 0 / 1（有问题）/ 2（用法错）。查 6 类：
    1) 所有 *.sh 的 bash -n 语法；
    2) Markdown 代码围栏是否闭合（含 ```` ``` ```` 与 `~~~` 混用时的字符 / 长度判断）；
    3) 行内反引号按 CommonMark 真规则配对：长度 N 的串要由下一个长度恰好为 N 的串闭合
       （所以 ```` ``` ```` 这种包法是合法的；"行内裸三连反引号"会被判错——正是上次那处真错）；
    4) 表格每行列数和表头一致；
    5) 内部链接指向的文件存在；
    6) frontmatter：SKILL.md 要 name + description，.mdc 要 description，值要符合
       YAML 明文标量规则（明文值里出现 ': ' 或 ' #' 会被当成新键/注释 → 判错）。
  - 接进 pre-commit（coop-hook.sh 的第 3 步），所以是"提交前拦住"。
  - 用 bash + awk + git 写，**不引 python/perl**：工具链一直是 bash+awk，钩子在
    任何装了 git 的机器上都得能跑。

  关键取舍：
  1) **扫描范围默认保守**：只查 agents-cooperation/ + .cursor/rules/agents-cooperation.mdc +
     本 skill 的 SKILL.md/references/assets/。理由：钩子若连 .cursor/skills/ 下别的 skill
     一起查（skill-creator 有二十来个文档），别人的文档不规范就会挡住本仓库的提交——误伤。
     要全查用 `--all`，那是人主动要的。
  2) 独立成脚本，不并进 coop-lint：lint 管"协作块格式"，体检管"文件语法"，两件事；
     钩子串起来跑就是一次提交前的完整门禁。
  3) 只做**结构**检查，不假装能证明"文档意思对"。也不假装能替代 shellcheck
     （本机没装；未定义变量、误引用这类查不出来，这一条要写在文档里，别让人以为"绿了=没错"）。

  验收标准：
  - [x] bash -n 覆盖全部脚本（模板 + 仓库副本）
  - [x] 故意造错：围栏不闭合 / 行内裸三连反引号 / 表格少一列 / 链接指向不存在文件 /
        描述里写 ': ' → 每一种都能定位到 文件:行 并退 1
  - [x] 健全的仓库上跑 → 退 0，且输出别噪（安静时一行总结）
  - [x] 接进 pre-commit：造一个语法错的文档，git commit 被拦；改掉就能提交
  - [x] `--all` 能扩到整个 .cursor/skills；显式路径也能查
  - [x] 回归断言覆盖上面每一条（selftest 128 → 146 条）

  遗留问题：
  - 只做结构检查，不证明语义；也不等于 shellcheck（本机没装）。输出里已经写明这句，别让人当成"没错"。
  - 已知漏报：文档里出现**两处**行内裸三连反引号时，它们会按 CommonMark 互相配对，
    于是查不出来（而渲染结果其实是坏的：中间整段会变成代码）。想抓这个得上更聪明的判据，
    风险是误报——按"误报比漏报更糟"处理，暂时认下这条漏报，写在 pitfalls D6 里。
  - 默认范围不含别的 skill，所以本仓库提交时**不会**发现 skill-creator / autoreview 的文档问题
    （`--all` 才查；试过，目前它们是干净的）。
