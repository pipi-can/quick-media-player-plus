  目标：让多个 AI（Cursor / opencode / 其他）和人轮流改这个仓库时，共用一条实现思路，
  而不是各写各的、后来者从头猜前人的意图。

  背景 / 为什么：仓库里已经有 qt-architecture / qt-code-style 两份规则管"代码怎么写"，
  但没有管"为什么这么做、改到哪一步了、这版有什么取舍"。换一个 agent 接手，这些信息就丢了。
  所以引入一层"协作块"记录：一个功能一个文件夹，一个块记一条思路，提交挂到块上可反查。

  落点（这次新增的文件）：
  - .cursor/rules/agents-cooperation.mdc      —— 常驻规则：动文件前先过"三问"判断要不要登记
  - .cursor/skills/agents-cooperation/         —— skill：完整流程 + references/ + assets/ 脚本
  - agents-cooperation/                        —— 协作数据目录（本块所在处，脚本由 coop-init 铺入）
  - agents-cooperation/_repo/build.md          —— 本仓库怎么构建 / 怎么跑（照 README 抄）

  关键取舍：
  1) "要不要登记"不按文件类型、只按三问（行为变了？别人依赖的东西变了？有取舍吗？）。
     宁可多记一条，也别让后来者猜。拿不准就问用户。
  2) 不登记的改动也要提交，但正文必须带 `Coop-Skip: <原因>`，让"为什么没登记"可事后审计；
     而不是用 --no-verify 绕过钩子。
  3) 块**只作废、不删除**（[Valid]: false）。删块会让编号被回收，`Coop-Block` 反查就串台。
  4) 脚本只管"机械的活"（编号、校验、回写、查块）；判断类的（该不该建块、代码好不好）交给人 / agent。
     分数只能由 agent 打——打分掺进脚本就变成"机器给自己发奖状"。
  5) 登记是"两次提交"：先提交代码 + 块，再用 coop-record 把 sha 回写进块并提交一次。

  约束：
  - 块字段顶格、半角冒号、顺序固定：Index < Valid < Author < Title < GitBranch < GitCommitIds < Comments；
  - `_` 开头的路径不是协作块；
  - 示例文档放 skill 的 references/，不要放进 agents-cooperation/（会被当成真块统计）。

  验收标准：
  - [x] 写代码前能先查到同功能的块；没有就提示先建块（新功能先问用户）
  - [x] 提交后 `git log --grep='^Coop-Block: 1$'` 能反查到这次实现
  - [x] `coop-lint.sh` / `selftest.sh` 全绿
  - [x] 装钩子后，缺 trailer 的提交被拦、带 Coop-Block 或 Coop-Skip 的放行

  遗留问题（opencode-agent，见本次提交）：
  - 两个 agent 同时改同一篇块文档会丢更新（coop-record 是整文件重写，没做合并）。
  - 块会过期：代码大改而没人动块时，[Valid]: true 的块可能已是过期地图。要对冲得给块加
    "最后复核"信号 + lint 检查块里引用的文件是否还在。
  - 编译验证没有强制力：没有机器检查能证明"真的编译过"，只能靠提交正文 + _repo/build.md 可复现。
  - 本块是"补登记"：代码先写完了才建块。正常流程应该"先在块里写目标/验收，再写代码"。

  后续补充（opencode-agent，见 [GitCommitIds] 最新一项）——第一次真实试用后修的两条：
  - 试用发现"脚本存两份"（模板 `.cursor/skills/.../assets/` 与仓库副本 `agents-cooperation/*.sh`）会摇：
    于是把同步**显式化、可对账**：coop-init 逐个报告 新建/更新/未变，新增 `--check-sync` 对账（漂移退 1）。
    规矩定死：**改脚本只改模板，再同步；别直接改副本**。
  - 试用发现 `coop-init.sh --hooks` 有隐藏副作用：只想装钩子，却把 10 个脚本又覆盖了一遍。
    改成 `--hooks` 只装钩子（要求数据目录已铺好），不再碰脚本。
  - 这一轮新增 21 条回归断言（selftest 103 → 124 条量级），专门盯上面两条 + "不覆盖未提交的手改"。

  后续补充二（opencode-agent，见 [GitCommitIds] 最新一项）——语法/退出码体检顺手修的：
  - `coop-find.sh --help` 打印了用法却退 1（`usage()` 无条件 `exit 1`）。帮助是用户主动要的，
    改成退 0；"不带参数"这种用法错误仍退 1。补了 3 条断言（--help / -h 退 0、无参数退 1），
    现在 selftest 128 条。

  后续补充三（opencode-agent，见 [GitCommitIds] 最新一项）——把工具收进 _tools/：
  - 起因：用户看了一次协作目录就问了——"根目录怎么那么多脚本？这不是用来记录的吗？"。
    点得对：根目录 10 个脚本 + 1 个解析库（1814 行）躺在"记录"旁边，真正属于记录的只有
    3 份块文档。工具的体量盖过了它服务的对象。
  - 做法：仓库副本从 `agents-cooperation/*.sh` 挪到 `agents-cooperation/_tools/*.sh`。
    根目录之后只剩：功能文件夹（块文档）、`_repo/`（怎么构建）、`_tools/`（工具）、
    `index-reserved.txt` + `.gitignore`。用 `_` 前缀是照既有规矩——`_` 开头的路径本来就不参与
    块解析（`_repo/` 就是这么办的），不用为它新开例外。

  关键取舍：
  1) 只搬**副本**，正本仍在 skill 的 assets/（模板→副本那条规矩和护栏一律照旧，见 D5）。
  2) `COOP_ROOT` 不能再简单等于"脚本所在目录"。新规则：脚本目录的基名是 `_tools` 就上跳一层。
     没采用"往上找最近的 index-reserved.txt"——那等于让脚本猜文件，而新铺的目录可能还没生成它。
  3) 旧布局必须能迁移，不能两套并存（否则同一个脚本两个地方各一份，漂移风险翻倍）。
     coop-init 检测根目录的遗留 *.sh：内容与新副本一致就删掉旧的那份；内容一致之外的，
     只有确认**git 里已有备份**才搬，否则停下退 1（沿用 D5 的护栏，宁可让人来处理）。
     护栏的判据第一版写成"路径有没有被跟踪"——结果搬家后新路径未跟踪，11 个副本全被冤成
     "有未提交的手改"，同步整个被挡住（真实踩到）。改成**内容级**：把文件算成 blob 问对象库
     有没有（`git hash-object` + `git cat-file -e`）。已提交的、`git add` 过的、内容碰巧等于
     历史版本的，都算有备份、允许覆盖；只有"git 里真没有的那份手改"才拒。判据更准，还顺带
     去掉了上一版为兼容搬家而加的 `moved_set` 小聪明。
  4) **已经有仓库的钩子壳会静默失效**：壳子是 `[ -f "$root/agents-cooperation/coop-hook.sh" ] || exit 0`，
     脚本一搬家，这个路径就没了 → 钩子直接放行，门禁悄悄关掉。所以 coop-init 要能认出
     "是我们装的壳子、但指向废弃路径"，自动改写并明说。这条比布局本身更重要：静默失效比报错坏得多。
  5) 文档里的命令写法全跟着改（`./agents-cooperation/_tools/coop-new-block.sh`）。
     命令变长是这轮唯一的代价，换目录干净；写在文档里一致就行。

  验收标准：
  - [x] 新布局铺出来：根目录没有 *.sh，脚本都在 _tools/ 下
  - [x] 旧布局自动迁移；内容 git 里没备份的遗留脚本不搬、明确报错并退 1
  - [x] 钩子壳指向 _tools/coop-hook.sh；指向旧路径的会被改写并提示
  - [x] 从 _tools/ 跑脚本时 COOP_ROOT 仍等于协作目录根（编号锁、index-reserved.txt、块文档都在根上）
  - [x] selftest 全绿（175 条，含新增的布局 / 迁移 / 钩子路径断言），--check-sync 干净

  这一轮的自评（A 档 37/40，opencode-agent）：
  - 可读性 -1：`content_is_recoverable()` 用"算 blob 问对象库"这层间接，注释写了原因
    （不写的话后人看到 `hash-object` 会以为是取 sha 用），但比"看 git status"难读一点。
  - 最小实现 -1：迁移 + 钩子改写（约 40 行）是为"不留两套布局 + 门禁不许静默失效"付的账；
    只搬脚本本身可以不写这些，但那样这次改动就是**会悄悄拆掉门禁**的那种。
  - 协作风格 -1：块里的历史段落（前几轮的 [Comments]）里 `agents-cooperation/*.sh` 的旧说法
    没改——那是历史记录，改了反而失真；代价是读旧段落时会看到过期路径。
  - 遗留问题：① 同一次"迁移 + 同步"里，若副本内容是自己上一轮刚写进工作区、还没进 git 的，
    同步仍会拒（提示已写明"提交或 git add 一次再重跑"）；② `find_template_dir` 的候选路径仍
    是硬编码（skill 装到非常规位置时得从 assets/ 里跑）。

  自评扣分（B 档 35/40，opencode-agent，见 [GitCommitIds] 最新一项）：
  - 最小实现 -2：为"脚本存两份"补了 --check-sync 和 find_template_dir（含 4 条硬编码候选路径），
    算多出来的机器件；模板装到别的位置时只能靠猜，没法指定目录（退 2 后就没有别的办法）。
  - 协作风格 -1：那 4 条候选路径是脚本里第一处硬编码"工具装在哪"的布局知识，
    而别的脚本都把布局知识留在文档里。
  - 可读性 -1：模板脚本不能写死某个仓库的块号，所以 coop-init.sh 里没有"见协作块 #N"的回指。
  - 过程顺序出过岔子：这一轮是先提交、后打的分（细则要求先自评再提交）。扣分项是补记进本段的。
