# 容易出问题的地方（以及怎么避开）

这份是**已知风险清单**。每一条都是实测过的（不是推测），附上现象、原因、办法。

怎么读：先看 **A 类**（会算错、丢数据），再看 **B 类**（会看错、漏看），C 类是协作习惯问题，D 类是工程化（大部分已经补上），E 类是**验证与验收**（自欺欺人的高发区）。

---

## A 类：会算错 / 丢数据

### A1. 两个 agent 同时算编号 → 撞号

- **现象**：两个 agent 各处建块，拿到同一个号；`Coop-Block: 3` 反查指向两批提交。
- **原因**：编号是"读当前最大值 +1"算出来的，天然有竞态。
- **办法**（已做三层防护，见 [scripts.md](scripts.md#编号租约防两个-agent-撞号)）：
  1. `coop-new-block.sh` 取号时**上锁**，"算号 + 写块"原子完成 → 同一工作区并发安全；
  2. 取号后登记到 `index-reserved.txt` → 跨分支/克隆安全，**但必须提交、别人 pull 了才算数**；
  3. `coop-lint.sh` 撞号直接报错（兜底）。
- **剩下的风险**：两个人各自建块、都还没提交、也没 pull → 仍会撞。所以还是建议**一个 agent 负责一个功能文件夹**、**建块后尽早提交**、回写前 `git pull --rebase`。

### A2. 仓库不是 git 仓库（或用别的 VCS）

- **现象**：`coop-record.sh` / `coop-history.sh` 直接失败（拿不到 sha / 分支）。
- **原因**：整个流程（`Coop-*` trailer、`[GitCommitIds]`）建立在 git 上。
- **办法**：**先问用户**。要么让用户 `git init`，要么退化成"只写块、`[GitBranch]` / `[GitCommitIds]` 永远 `null`"——但要说清楚这样就没有"哪次提交实现了它"这条线索了。

### A3. rebase / amend / squash 之后 sha 失效

- **现象**：`[GitCommitIds]` 里的短 sha 在仓库里找不到了。
- **原因**：改写历史后对象变了，短 sha 本来就只是"当时的地址"。
- **办法**：`coop-history.sh` 会打印"找不到这个提交"并提示重找；用锚定的反查拿新 sha：

  ```bash
  git log --format='%h %s' --grep='^Coop-Block: 3$'
  ```

  把失效的换掉，并在提交消息里写明。

### A4. 删掉块 → 编号被回收 → 反查串台

- **现象**：删了块 5，下一个新块又拿到 5；`Coop-Block: 5` 同时指向旧实现和新实现。
- **原因**：编号只从"现存的块"算最大值。
- **办法**：**块只作废（`[Valid]: false`），永不删除**。`coop-init.sh --hooks` 装的 pre-commit 会在删块时直接拦下提交（纯数字编号和 `ren-1` 这种人类编号都覆盖）；没装钩子的仓库就靠这条约定 + review。

### A5. 工具"报成功"，其实一个字都没写（静默失败）

- **现象**（真实踩过）：`coop-record.sh` 碰上**缺 `[GitBranch]` / `[GitCommitIds]` 字段**的块、或 **CRLF 行尾**的块，会打印
  "已回写块 #N … 提交(新→旧): [\"abc1234\"]" 并且 **退出码 0**，但文件根本没变——提交线索就这么丢了，还没人知道。
  根因："读块字段"和"写块字段"在两处各手写了一遍 awk，行为不一致（一处去了 `\r`、一处没去；一处只会替换、不会插入）。
- **为什么最危险**：这不是"报错"，是"骗你成功了"。协作链路的信任就毁在这种地方。
- **办法**（已经做了，别改回去）：
  - 块字段的读写**只有一个实现**：`_coop-common.sh` 的 `coop_get_field` / `coop_set_field`（围栏感知、CRLF 安全、字段不存在时按字段顺序插入）；
  - `coop-record.sh` 写完后**自检**：重读一遍核对，对不上就报错退出（宁可失败，也不报假成功）；
  - `selftest.sh` 针对"缺字段 / CRLF / 多块文档 / 围栏"各留了一条断言。

  > 一般化的教训：**"写"这类动作，要么校验返回值，要么有回归测试**。凡是"打一句成功就完事"的写操作，都值得怀疑一次——尤其是它同时还在报"我改好了"。

## B 类：会看错 / 漏看

### B1. 文档里演示块格式 → 幽灵块

- **现象**：文档里写了一小段"格式长这样"的示例，结果被当成真块，编号全乱。
- **原因**：解析器按"顶格 `[字段]:`"认块，分不清示例和真块。
- **办法**：**把示例放进围栏代码块**（```` ``` ```` 或 `~~~`）。解析器现在会整段跳过围栏内容（已修）。围栏没闭合会被 `coop-lint.sh` 报错——因为一旦没闭合，后面的块会被整段跳过。
  另外行内提到围栏标记时，要用**四连反引号把三连包起来**（写法见本文其它地方，别自己现编）；直接写裸三连会被
  `coop-docs-check.sh` 判成"反引号没配对"（它按 CommonMark 的同长度配对规则查）。

### B2. `[Comments]` 里顶格写出 `[Index]: …`

- **现象**：注释正文里顶格写了一句 `[Index]: 77`，结果被当成一个新块开始，原块被从中间切开。
- **原因**：字段顺序倒退 = 新块，这是刻意的设计（这样人类块省掉 `[Index]` 也能切）。
- **办法**：正文里的字段示例**缩进一级**，或放进围栏代码块。`coop-lint.sh` 会对"被缩进的字段"发警告，对切出来的半个块（缺 `[Author]`/`[Title]`）报错。

### B3. 全角冒号 `：`

- **现象**：中文输入法打出 `[Index]：3`，旧版脚本完全看不见这个块（静默丢失）。
- **原因**：旧解析器只认半角 `:`。
- **办法**：解析器现在**两种冒号都认**（已修），同时 `coop-lint.sh` 会**报错要求改回半角**——因为别的工具和人容易看错。

### B4. 字段名大小写（`[index]:`）

- **现象**：同上，静默丢失。
- **办法**：解析器现在大小写不敏感（已修），`coop-lint.sh` 报错要求写成规范形式 `[Index]`。

### B5. 字段被缩进

- **现象**：从别处粘贴过来，整块被缩进两格 → 一个块都不认。
- **办法**：`coop-lint.sh` 警告"字段被缩进了"；`[Comments]` 的正文才该缩进，字段本身必须顶格。

### B6. `.md` 里没有块（放错文件）

- **现象**：把说明文档放进了 `agents-cooperation/`，`get-index.sh` 里看不到它，但也没人发现它没用。
- **办法**：`coop-lint.sh` 警告"一个协作块都没解析到"。**说明文档不要放在协作目录里**，放 skill 的 `references/`。

## C 类：协作习惯（靠约定，脚本管不了）

### C1. 两个 agent 同时改同一篇 md

- **现象**：git 合并冲突；即使不冲突，也可能一方覆盖另一方的块。
- **办法**：尽量**一个功能一个文件夹、一个文件夹一个人**；改之前先看 `git status` / `git pull`；冲突时**不要自己挑一边**，问用户。块都是**追加**到文档末尾的，冲突通常就是"两边都追加"——保留两个块即可。

### C2. AI / 人 靠名字尾缀判断

- **现象**：某个工具署名叫 `claude-code`（不以 `agent` 结尾）→ 被当成人类块，编号变成 `claude-code-1`。
- **办法**：约定**必须**写 `<工具>-agent`（`cursor-agent`、`opencode-agent`、`claude-agent`……）。不按约定的，`get-index.sh` 会把它列进"缺编号的人类块"，也还能用，只是分类不准。

### C3. 提交消息不带 `Coop-*` trailer

- **现象**：`git log --grep='^Coop-Block: 3$'` 搜不到那次提交，反查断链。
- **办法**：`coop-init.sh --hooks` 装的 `commit-msg` 钩子会直接拦下（已经做了）。没装钩子的仓库只能靠 rule 和 review 兜。

### C3b. 拿 `Coop-Skip` 当挡箭牌

- **现象**：明明改了行为 / 接口，却写 `Coop-Skip: 小改动` 糊过去——协作目录里就没有这条记录了。
- **为什么危险**：`Coop-Skip` 是为了**放行纯文案 / 格式 / 笔误**，一旦被滥用，整条协作链路的可信度就没了。
- **办法**：判断只用三问（行为变了？别人依赖的东西变了？有取舍吗？），**拿不准就按"要登记"**。事后可审计：`git log --grep='^Coop-Skip:'` 把所有"没登记"的提交列出来（建议 review 时扫一眼）。规则文件第一节就是这条边界。

### C4. 把"回写提交"也记进 `[GitCommitIds]`

- **现象**：数组里混进了纯登记用的提交，读的人以为那也是实现。
- **办法**：`[GitCommitIds]` **只记实现提交**；回写那次不记（但它的消息照样带 trailer）。历史反查时可能会捞出回写提交，属正常。

### C5. detached HEAD

- **现象**：`[GitBranch]` 变成 `HEAD`，后来者切不过去。
- **办法**：`coop-lint.sh` 对这个发警告。

### C6. 多个分支 / git worktree 并行

- **现象**：各分支上编号各算各的，合并后才撞；worktree 里各有一份协作目录。
- **办法**：编号预留表（`index-reserved.txt`）提交 + pull 能挡住大部分；合并前跑 `coop-lint.sh`；并行开发时功能文件夹分开。

## D 类：工程化

### D1. 搬到一个新仓库 —— 已补

见 [install.md](install.md)：复制哪些文件、`opencode.json` 怎么注册、Cursor / 别的 agent 怎么配、装钩子的顺序。

### D2. 强制校验 —— 已补

`coop-init.sh --hooks` 装 `pre-commit`（跑 lint + 防删块）和 `commit-msg`（查 trailer）。钩子是仓库外挂的，**每个克隆都要装一次**。

### D3. 数据目录里混入非块文档

见 B6。目前是**警告**，没升级成硬规则。

### D4. 脚本自身没有测试就会退化 —— 已补

`selftest.sh`（全套回归，最后一行打印「通过 N，失败 M」）。**改脚本不跑它，就会出上次那种"输出少一行"的低级问题**——更险的是那种"报成功、其实没写"的静默失败，只有回归能兜住。

### D5. 脚本有"模板"和"副本"两处，改错地方 / 忘了同步 —— 已补

- **现象**：`agents-cooperation/*.sh` 是 `coop-init.sh` 从 skill 的 `assets/` 同步过去的**副本**。
  直接改副本 → 下次同步被覆盖（悄悄回退）；改了模板忘了同步 → **仓库里跑的还是旧脚本**（而且没人知道）。
- **为什么危险**：第二种是静默的——你以为改好了，实际执行的是旧代码。
- **办法**（已经做了）：
  - `coop-init.sh` 同步时**逐个报告** `新建 / 更新 / 未变`，有更新还会提醒你看 `git diff`——不再闷声覆盖；
  - `./agents-cooperation/coop-init.sh --check-sync` 随时对账，有漂移退 1；
  - 同步要覆盖副本时，如果那份副本有**还没提交**的手改 → **跳过不覆盖**并退 1（覆盖了改动就真丢了）；
    已经提交过的手改则允许覆盖——git 里留着，翻得回来。顺手提醒你看 `git diff` 再决定提交什么。
  - `--hooks` **不再顺带复制脚本**（以前它是个隐藏副作用：只想装钩子，却把脚本覆盖了一遍）。
  - 规矩一句话：**改脚本只改模板（skill 的 `assets/`），然后同步**。

### D6. 写"检查脚本"本身最容易出的两种错：判据过窄（误报）和吹过牛（包不了它包不了的）—— 已补

- **误报比漏报更糟**：检查脚本一旦冤枉合规的文件，人就会开始无视它（或者拿 `--no-verify` 绕），
  这个门禁就废了。真实案例：`coop-docs-check.sh` 第一版按**逐行**判断反引号配对，
  于是把"一个 code span 跨两行"这种**完全合法**的 Markdown 判成错（`autoreview` 的文档就被冤枉了）。
  真相是 CommonMark 允许反引号串**跨行**配对——判据得按整篇文档排成一条队列来配。
- **办法**（已经做了）：
  - 判据按**规范**写，不按"看着像"写（去查 CommonMark 的配对规则，而不是拍脑袋）；
  - 拿**别人的真实文档**跑一遍 `--all` 当试金石：误报会在那里暴露；
  - 默认扫描范围**只查自己的文件**，别人 skill 的文档要人主动 `--all` 才查——误伤别人的东西最招人烦；
  - 会冤枉人的规则宁可降级成"不查"，也不硬报（比如"两处行内裸三连反引号互相配对"这种漏报就认了，
    写在这里说明白，而不是加个更聪明的启发式去猜）。
- **别吹牛**：`coop-docs-check.sh` 只做**结构**检查。它不证明"文档意思写对了"，也不等于 shellcheck
  （未定义变量、误引用、逻辑错查不出来）。它的输出里就写着这句，免得后人把"绿了"当"没错"。

## E 类：验证与验收（新增，都是自欺欺人的高发区）

### E1. 没编译就说"做完了"

- **现象**：「代码写好了，逻辑上应该没问题」——没编译，也没说没编译。
- **为什么危险**：这是最容易被信任的一句话，也最容易是错的。用户以为验证过了。
- **办法**：没编译过就不算写完。真编不了就明说"没编译，因为 X"。见 [build-verify.md](build-verify.md)。

### E2. 编译失败，但没分清是自己的锅还是环境的锅

- **办法**：`git stash` → 重编。同样的错 = 环境/既有问题；不同了 = 你的锅。**把依据写出来**，否则用户没法判断该不该信你。

### E3. 把"环境缺失"说成"代码没问题"

- **现象**：「构建命令报了错，应该是环境没配好」——没贴报错、没做对照。
- **办法**：命令原文 + 关键报错前 10 行 + `文件:行` + "环境缺失"和"代码问题"分开写。

### E4. 自评给自己满分（无证据）

- **现象**：四个维度全是 10/10，理由栏空着或写"良好"。
- **为什么危险**：评分一旦变成仪式，它就只是给流程盖章，review 的人也会开始不信这张表。
- **办法**：每条扣分**指到 `文件:行` 并贴代码**；必须写"我最不放心的三点"——真要是 40/40，这三点就是最难写的部分。

### E5. 只评"代码好不好"，不对照"验收标准做没做到"

- **现象**：分数打得挺细，但块里 `[Comments]` 写的验收标准一条都没提。
- **后果**：功能没做完这件事**悄悄消失**了。
- **办法**：打分之前先做「验收对照」，逐条打勾；没做到的写进块里的遗留问题。

### E6. 删了模块，但忘了（或擅自）处理对应块

- **两个方向都会错**：① 删完代码就完事，块还是 `[Valid]: true`，后人照着过期思路继续写；
  ② 反过来自己就把块置 `false` 了，没问用户。
- **办法**：`coop-find.sh` 找出依赖它的块 → 清单报给用户 → **等同意** → 置 `false` 并在 `[Comments]` 记一句原因（**块不删**）。

### E7. 块里的 `[Comments]` 是"写完之后的总结"

- **现象**：先写完代码，再回头补一段思路；或者干脆不写新块。
- **后果**：块里记的是"结果"，不是"当时的取舍"——它解释不了"为什么不选另一条路"，而这恰恰是后来者最需要的。
- **办法**：新功能就是"**先问 → 建块写思路 → 再写代码**"；思路是动手前的共识。

## 还没解决 / 需要人判断的（认了）

- **要不要参考某条已有思路**、**该不该问用户**、**代码怎么写**、**这版代码好不好**——这些都是判断，脚本化不了（脚本只能把材料摆齐）。
- **提交消息写得有没有思路**——机器只能查"有没有 trailer"，查不了"写得好不好"。
- **"块重复不重复"这种语义问题**——只能靠 `[Title]` 写清楚 + lint 的同名警告。
- **块会不会过期（知识腐化）**——目前没有对冲机制：块只在"有人动手"时才被更新，代码大改而没人动块时，`[Valid]: true` 的块可能已经是过期地图。
  现在的缓解只有：验收对照 + 自评打分时顺带读一遍块、以及"删模块必须找块"这条。**真要做保鲜，得给块加"最后复核"信号 + lint 检查块里引用的文件是否还存在。**
- **评分的主观性**——同一份代码，两个 agent 可能打 32 和 36。这份细则靠"扣分必须指到 `文件:行`"来压低方差，但压不到零；**分数是给人看的证据，不是结论**。

## 自检（提交前一条条过）

- [ ] 先答过"要不要登记"三问：是**行为 / 接口 / 取舍**里的哪一种，还是真的只是文案 / 格式 / 纯登记。
- [ ] 跑过 `./coop-lint.sh`，没有错误。
- [ ] 新块是用 `coop-new-block.sh` 建的（不是自己手写编号）。
- [ ] 没有两个块共用一个编号。
- [ ] 演示/示例都放在围栏代码块里，围栏成对闭合。
- [ ] 字段顶格、半角冒号、规范大小写。
- [ ] 提交消息：要登记的带 `Coop-Block` / `Coop-Folder` / `Coop-Author`；不登记的带 `Coop-Skip: <原因>`。
- [ ] `coop-record.sh` 跑过，并把回写提交提交掉。
- [ ] 没删块（要停用就置 `[Valid]: false`，且先问用户）。
- [ ] 装了钩子的仓库：这次提交没靠 `--no-verify` 蒙混过去（该带 `Coop-Skip` 的就带）。
- [ ] 评分时**同一个问题没有重复扣分**（比如"注释掉的代码"只在可读性扣，不再在"无残留"里扣一次）。
